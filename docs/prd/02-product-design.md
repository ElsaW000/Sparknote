# Spark Vault 产品设计

版本：v0.2 评审稿  
日期：2026-05-27

## 1. 设计原则

Spark Vault 的产品设计应围绕一个核心动作：把用户临时产生的内容整理成可复用的笔记。

设计原则：

- 记录要快。
- 整理要可控。
- 原文不能丢。
- AI 不能越界编造。
- 历史要能找回。
- 手机端路径要短。

## 2. 产品结构

推荐主结构：

```text
Home
Capture
Library
AI
```

不推荐继续把 Archive 放在底部 Tab。Archive 是结果查询，不是高频动作。

## 3. 模块职责

### 3.1 Home

Home 是状态总览和快捷入口。

承担：

- 展示最近记录。
- 展示核心指标。
- 提供快速记录入口。
- 提供最近 AI 整理入口。

不承担：

- 大量历史列表。
- 复杂设置。
- 长文本编辑。

### 3.2 Capture

Capture 是输入中心。

输入方式：

- 手动输入。
- 口述转文字。
- OCR / 截图识别。

Capture 的目标是尽快得到一段可编辑文本，然后交给 AI 或直接保存。

### 3.3 Library

Library 是内容资产库。

承担：

- 所有已保存 fragment。
- 搜索和筛选。
- 标签和来源管理。
- 收藏。
- 编辑和删除。
- 查看整理历史。

### 3.4 AI

AI 是整理中心。

只做：

- 整理文字。
- 总结内容。
- 生成标签。

不做：

- 延展续写。
- 代写文章。
- 编造观点。

## 4. Archive 处理方式

Archive 不作为一级 Tab。

推荐两种归属：

| 方案 | 说明 | 推荐度 |
| --- | --- | --- |
| 放入 Library | 作为“整理历史”筛选或二级页 | 高 |
| 放入 AI | 作为“最近整理”历史入口 | 中 |

当前建议：历史结果进入 Library，因为用户最终找的是内容资产，不是单次 AI 行为。

## 5. AI 整理交互

AI 整理必须展示四块内容：

1. 原始文本。
2. 整理后正文。
3. 摘要。
4. 标签。

用户必须可以：

- 编辑整理后正文。
- 编辑标签。
- 放弃结果。
- 保存结果。

保存后，Library 中应能看到整理后的笔记，同时保留原文。

## 6. 口述转文字交互

推荐路径：

```text
Capture -> 口述记录 -> 开始录音 -> 停止录音 -> 转写 -> 编辑文本 -> AI 整理 -> 保存
```

关键状态：

- 未授权麦克风。
- 录音中。
- 转写中。
- 转写成功。
- 转写失败。
- 用户取消。

## 7. 视觉设计方向

继续沿用 Android 原型方向：

- 暖白背景。
- 白色卡片。
- 深蓝主色。
- 浅紫标签。
- Material 3 风格。
- 轻量、安静、偏工具型。

避免：

- 营销型首页。
- 过重装饰。
- 大面积渐变。
- 把内容包在多层卡片里。

## 8. 核心设计判断

当前产品最重要的不是“生成更多内容”，而是“让用户已有内容变清楚”。

所以 v0.2 应聚焦：

- 输入能力增强：口述转文字。
- 整理能力增强：大模型清理、总结、标签。
- 信息架构简化：Archive 降级。
