# Spark Vault 用户使用路径

版本：v0.2 评审稿  
日期：2026-05-27

## 1. 路径一：手动输入整理

```text
打开 App
-> Capture
-> 手动输入文字
-> 点击 AI 整理
-> 查看整理后正文、摘要、标签
-> 用户编辑确认
-> 保存
-> Library 查看
```

成功结果：

- Library 出现新笔记。
- 原文和整理后正文都被保留。
- 摘要和标签可搜索。

## 2. 路径二：口述转文字整理

```text
打开 App
-> Capture
-> 口述记录
-> 授权麦克风
-> 开始录音
-> 停止录音
-> 转写成文字
-> 用户编辑转写结果
-> AI 整理和总结
-> 保存
-> Library 查看
```

异常路径：

- 未授权麦克风：提示开启权限。
- 转写失败：提示失败，允许重新录音或手动输入。
- 转写为空：不允许保存。

## 3. 路径三：从 Library 找回内容

```text
打开 App
-> Library
-> 输入关键词
-> 选择来源或标签
-> 打开笔记详情
-> 查看原文、整理后正文、摘要、标签
```

成功结果：

- 用户能在 10 秒内找到目标内容。
- 筛选条件可组合。
- 没有结果时显示空状态。

## 4. 路径四：AI 整理已有笔记

```text
打开 App
-> Library
-> 打开一条笔记
-> 点击重新整理
-> 进入 AI
-> 生成整理后正文和摘要
-> 用户确认保存
```

说明：

- 该路径适合旧笔记重新处理。
- 保存时不覆盖原文。
- 可以更新 cleanedText、aiSummary、tags。

## 5. 路径五：查看历史整理

推荐路径：

```text
打开 App
-> Library
-> 整理历史
-> 打开历史结果
-> 查看关联笔记
```

备选路径：

```text
打开 App
-> AI
-> 最近整理
-> 打开历史结果
```

结论：

Archive 不作为一级路径。历史是辅助回看，不是主操作。

## 6. 路径六：合并多条笔记

```text
打开 App
-> Library
-> Merge Fragments
-> 选择至少两条 fragment
-> 输入合并标题
-> 确认合并
-> 生成新 fragment
```

异常路径：

- 少于两条：提示至少选择两条。
- 合并失败：提示错误，不删除原内容。

## 7. 主路径总结

v0.2 的主路径应该收敛为：

```text
记录
-> 转文字
-> 整理总结
-> 保存
-> 查找复用
```

不建议把用户主路径设计成：

```text
记录
-> 生成长文
-> 归档报告
```

原因：

- 这会让产品过早变成写作生成器。
- 当前更核心的问题是用户原始内容太乱，需要先整理。
- Archive 单独成 Tab 会放大低频能力，削弱记录和整理主路径。
