# ADR-0001: uni-app 迁移基础原则

状态: Accepted
日期: 2026-05-29

## 背景
项目正从安卓端能力迁移到 uni-app，需要在快速交付和长期可维护之间取得平衡。

## 决策
- 采用分层架构: 页面层 / store / 逻辑层 / repository / API。
- 先建立本地可运行 MVP，再逐步接入后端能力。
- 关键业务逻辑必须可在 Node 环境独立测试。
- 路由与页面清单必须保持单一事实源（pages.json + migration checklist）。

## 影响
- 页面开发速度短期略慢，但后续扩展更稳定。
- 测试成本前置，但回归成本下降。
- 文档维护成为强制流程的一部分。

## 备选方案
- 直接在页面内写业务逻辑。
- 只做手工测试，不引入逻辑层自动化测试。

## 不采用原因
- 会造成页面臃肿、回归风险高、多人协作成本高。

## 后续行动
- 按 MVP 计划落地 services/store/tests。
- 每次架构变化新增 ADR 或更新现有 ADR。
