# 交付节奏与执行方式

状态: Active
更新时间: 2026-05-29

## 执行节奏（建议）
- 每个迭代周期: 2-3 天
- 每个迭代包含:
  - 需求对齐
  - 实现
  - 验证
  - 文档回写

## 任务推进规则
- 一个任务只允许一个 in-progress 子项。
- 代码改动完成后必须补验证记录。
- 未更新文档视为任务未完成。

## 里程碑
- M1: 完成纯逻辑 + repository/store + 单测
- M2: 完成 5 大主页面联动（本地数据）
- M3: 完成后端核心接口接入
- M4: 完成稳定性验证与发布准备

## 每日检查清单
- 今天是否有可运行的最小成果。
- 今天是否增加了自动化验证。
- 今天是否更新了 checklist 与 ADR。
