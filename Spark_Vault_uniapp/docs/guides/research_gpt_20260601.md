重新整理后的判断如下。

你的产品现在不要继续围绕“AI 日记”“AI 心理成长”“名人导师”去讲。那个方向会撞竞品，也容易把产品带到心理咨询、情绪陪伴、角色扮演的风险区。更稳定的核心是：

**Spark Vault 是一个个人成长型知识与实践复盘工具。它帮用户把学到的知识、真实经历和实践反馈放在一起对照，最后沉淀成自己的方法论。**

英文可以暂定为：

**Spark Vault helps you turn what you learn and what you live into your own personal playbook.**

中文：

**Spark Vault 帮你把学到的知识和真实经历，沉淀成自己的方法论。**

这句话比“个人证据引擎”“AI 反思系统”“思维模式追踪”都更适合。它保留个人成长感，也没有过度心理化。

你真正的差异点不是“降低 AI 幻觉”本身。更准确地说，是：

**所有洞察都基于用户自己的原始记录、学习资料和实践反馈，并且可以追溯引用。**

这点很重要。用户不需要相信 AI 的判断，他可以回看 AI 是从哪条日志、哪段书摘、哪篇文章、哪次实践反馈里得出的结论。这个机制降低幻觉，也降低用户被 AI 误导的风险。

产品核心闭环应该是四步：

第一，用户保存两类内容。
一类是 **Practice Notes / 实践记录**：日记、决策、沟通、项目复盘、行动结果。
一类是 **References / 参考资料**：书摘、文章、方法论、管理框架、课程笔记、他人观点。

第二，AI 做对照分析。
它不只是总结“你最近关注什么”，而是比较：你学到的东西和你实际做的事情之间有没有差距。

第三，AI 给出带引用的洞察。
每个结论都要能点回来源。比如：“这个判断来自 3 条实践记录和 2 条参考资料。”

第四，沉淀成个人方法论。
最终结果不是一份普通报告，而是一套不断更新的 **Personal Playbook / 个人方法论手册**。

你的产品灵魂可以写成这句：

**Spark Vault 不只是帮你保存想法，它帮你验证：哪些知识真的进入了你的行动，哪些还停留在收藏夹里。**

这就是目前最有差异的地方。

关于原来的产品设计，现有 4 Tab 结构可以保留：Home、Library、Chat、Me。文件里的设计本来已经包含 Library、AI Digest、Chat、报告、Skills、导师模式、创作辅助等模块，确实具备“记录 → 对话 → 报告 → 沉淀”的雏形。 之前对话里也已经把方向从“思维纠偏/AI 日记”推进到了“知识—实践—个人方法论”的定位。

但模块命名需要重新定，不要再频繁换成 Perspectives、Lenses、Advisors 这些词。你说得对，**Skills 可以保留**。

原因很简单：这个模块本质上是一个可复用的 AI 能力配置，不只是视角，也不只是角色。一个 Skill 可以包含：

角色定位
分析角度
学科框架
参考资料
引用规则
输出格式
边界限制
用户自定义引导问题

所以 **Skills** 比 Perspectives、Lenses、Advisors 更能容纳这个复杂度。

最终模块建议如下：

| 当前模块          | 建议名称                  | 中文          | 说明                                                |
| ------------- | --------------------- | ----------- | ------------------------------------------------- |
| 记忆纠偏          | **Pattern Review**    | 模式复盘        | 不要叫“纠偏”。纠偏像心理矫正。Pattern Review 更像复盘行为、决策和反复出现的模式。 |
| 大师导师 / Skills | **Skills**            | Skills / 技能 | 保留。它是可复用 AI 能力配置，可以包含人物角度、学科角度、方法论角度。             |
| 成长反思报告        | **Growth Report**     | 成长报告        | 简洁，低压力。报告内部再呈现知行差距、证据链、个人方法论。                     |
| AI Digest     | **Weekly Insights**   | 每周洞察        | 比 Weekly Evidence Digest 自然。证据链放在内容结构里，不放在标题里。    |
| 生成报告          | **Build My Playbook** | 生成我的方法论     | 这是差异点最强的动作，不只是“生成报告”。                             |

Skills 页面可以作为一个重要差异点来设计。不要让用户直接写 Prompt，要用引导式创建。

Create Skill 的页面结构建议是：

**1. What is this Skill for?**
这个 Skill 用来做什么？
选项：复盘决策、分析沟通、整理学习、生成方法论、辅助写作、项目复盘、自定义。

**2. What angle should it use?**
它应该从什么角度分析？
选项：管理学、产品思维、系统思维、第一性原理、苏格拉底式提问、某位思想家的方法论启发、自定义角度。

**3. Add References**
上传或选择参考资料。
这里是关键。用户可以上传书摘、PDF、文章、课程笔记、自己的方法论文档。这个 Skill 之后分析时要以这些资料作为知识依据。

**4. Choose what it can access**
选择它可以调用哪些内容。
选项：只看实践记录、只看参考资料、同时看实践记录和参考资料。

**5. Set citation rules**
设置引用规则。
比如：所有洞察必须引用来源；没有证据时要标注不确定；区分事实、推测和建议。

**6. Choose output format**
选择输出格式。
比如：简短建议、结构化报告、行动清单、个人原则、追问式对话、决策复盘。

**7. Test and save**
用一条记录测试，然后保存 Skill。

这样设计后，Skills 就不再是“名人角色扮演”，它变成了：

**Prompt + References + User Notes + Citation Rules + Output Format**

这很有价值。

关于名人或大师视角，可以保留，但不要作为主卖点，也不要做成“某某本人和你聊天”。更稳的做法是：

“芒格式思考”可以变成 **Mental Models Skill**
“苏格拉底”可以变成 **Socratic Questioning Skill**
“稻盛和夫”可以变成 **Work Philosophy Skill**
“管理学视角”可以变成 **Management Review Skill**

页面里可以写：
**Inspired by public ideas and frameworks. Not affiliated with or representing any real person.**

也就是说，可以借用思想框架，不要模拟真人身份。

产品主线最终应该是：

**Library 收集内容。**
包括实践记录和参考资料。

**Chat / Review 进行复盘。**
用户可以用某个 Skill 去分析自己的记录。

**Weekly Insights 做周期性洞察。**
每周告诉用户：你最近实践了哪些知识，哪些还没有落地，哪些模式反复出现。

**Growth Report 形成阶段性总结。**
报告里必须包含引用、证据、差距、验证结果和下一步建议。

**Playbook 沉淀长期方法论。**
这是产品终点，也是付费价值最高的地方。

最重要的产品表达可以固定成三句话：

**Save what you learn.**
保存你学到的东西。

**Review what you live.**
复盘你真实经历的事情。

**Build your own playbook.**
沉淀你自己的方法论。

中文：

**保存所学。复盘所行。形成自己的方法论。**

这版逻辑更稳。它保留“个人成长伙伴”，但避开心理诊断和名人模拟；它保留 Skills，但把 Skills 升级成带 References 和引用规则的 AI 能力配置；它保留报告，但报告的价值从“总结”升级为“证据链 + 知行差距 + 个人方法论”。




有几个地方值得记下来作为产品决策：

每条 AI 洞察必须能点回原始碎片 — 这是技术护城河，不是 UI 功能
个人内容 vs 参考内容的两分法 — 正好对应我们已经做进数据模型的 personal_content / reference_content，方向是对的
报告不是总结，是"出现频率 + 原文证据" — 这意味着报告生成的 prompt 需要要求 AI 引用原文，而不是自由发挥
