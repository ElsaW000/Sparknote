# 分形同构规则与代码映射规范

## 1. 目标

确保每一个功能“段落/代码片段”都有可追踪的 `MD 规则` 与 `实现映射`，形成回环闭环：

需求 -> 规则 -> API/模型 -> 前后端实现 -> 监控指标 -> 验收 -> 反哺需求。

## 2. 一级文档统一结构（必须同构）

每个一级类目文档必须包含以下 9 个区块：

1. `目标与边界`
2. `能力清单（Feature IDs）`
3. `闭环流程（事件流）`
4. `状态与数据模型`
5. `接口契约（API）`
6. `规则清单（Rules）`
7. `代码映射（Code Mapping）`
8. `指标与告警`
9. `验收标准`

## 3. 编号规则

- 功能编号：`{DOMAIN}-{NN}`，如 `TAG-03`
- 规则编号：`R-{DOMAIN}-{NN}`，如 `R-TAG-02`
- API 编号：`API-{DOMAIN}-{NN}`
- 映射编号：`MAP-{DOMAIN}-{NN}`

## 4. 代码段与 MD 对应规则（必须）

任意新增代码（前端/后端）都必须在对应一级文档中补一条映射：

- `MAP-*`: 代码文件路径
- `关联规则`: `R-*`
- `触发事件`: 用户动作或系统事件
- `预期输出`: UI变化/数据变化
- `失败处理`: 错误码 + 提示文案 + 日志字段

## 5. 回环同构（Loop）

固定闭环模板：

`Trigger -> Validate -> Persist -> Index/Link -> Notify/UI -> Observe -> Iterate`

- Trigger：输入触发
- Validate：规则校验
- Persist：写库
- Index/Link：索引/关联
- Notify/UI：返回给前端
- Observe：埋点与日志
- Iterate：数据回流到功能优化

## 6. 变更门禁

- 无 `R-*` 规则的代码变更，不允许合入
- 无 `MAP-*` 的 PR，不允许合入
- 验收标准与监控项未定义，不允许进入开发
