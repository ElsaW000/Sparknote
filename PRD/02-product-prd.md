# Sparknote PRD - Product Requirements Document

## 1. Executive Summary

**产品名称**: Sparknote  
**产品定位**: 创作者的AI灵感笔记本  
**核心价值**: 帮助创作者（小说家、产品经理、内容创作者）快速捕捉、整理和扩展灵感

---

## 2. User Personas

### Persona 1: 小说作者 - 小明
- **背景**: 25岁，网文作者，每天写3000字
- **痛点**: 灵感碎片散落在各个地方，经常忘记之前想的好的情节
- **使用场景**:
  - 走在路上突然想到一个情节，掏出手机快速记录
  - 记录人物设定（外貌、性格、背景）
  - 记录场景设定
- **期望**: 快速记录 + AI帮我扩展情节

### Persona 2: 产品经理 - 小红
- **背景**: 28岁，创业公司PM，需要管理需求
- **痛点**: 需求散落在微信、文档、邮件里
- **使用场景**:
  - 突然想到一个用户故事，快速记下来
  - 用AI把碎片的的需求整理成完整的需求描述
- **期望**: 快速记录 + AI整理 + 结构化存储

### Persona 3: 内容创作者 - 阿强
- **背景**: 30岁，短视频创作者，需要素材库
- **痛点**: 好的创意转瞬即逝，来不及记录
- **使用场景**:
  - 看到热门视频，记录灵感和选题
  - 用AI把选题扩展成完整的脚本大纲
- **期望**: 快速记录 + AI扩展 + 方便查看

## 3. Functional Requirements

### 3.1 用户认证

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 注册 | 邮箱+密码注册，**首次注册时选择身份定位** | P0 |
| 登录 | 邮箱+密码登录 | P0 |
| 身份定位 | 首次注册时选择：小说作者/产品经理/内容创作者/全部 | P0 |
| 登出 | 退出登录 | P1 |

### 3.2 核心交互：对话式记录

**参考Flomo**: 像发微博/聊天一样记录笔记，主页面是对话时间线

| 功能 | 描述 | 优先级 |
|------|------|--------|
| **对话式输入** | 主页面是对话输入框，像发消息一样记笔记 | P0 |
| 时间线展示 | 所有笔记按时间倒序展示，像聊天记录 | P0 |
| **热力图日历** | 用颜色区分标签分类，深浅表示数量 | P0 |
| 一键记笔记 | 首页底部输入框，直接发送就是创建笔记 | P0 |

### 3.3 标签系统（差异化设计）

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 手动打标签 | 输入#标签自动识别 | P0 |
| 标签颜色映射 | 不同标签类型显示不同颜色 | P0 |
| 颜色深浅 | 笔记越多颜色越深 | P0 |
| 按标签筛选 | 点击标签查看同类笔记 | P1 |

### 标签颜色映射（预设）

| 标签类型 | 颜色 |
|----------|------|
| #小说 | 🔵 蓝色 |
| #产品 | 🟢 绿色 |
| #内容 | 🟠 橙色 |
| #技术 | 🟣 紫色 |
| 其他 | ⚪ 灰色 |

### 3.3 笔记管理

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 查看笔记列表 | 时间线形式展示所有笔记 | P0 |
| 查看笔记详情 | 点击查看单条笔记完整内容 | P0 |
| 编辑笔记 | 修改笔记内容 | P0 |
| 删除笔记 | 删除笔记 | P0 |
| 搜索笔记 | 按标题/内容搜索 | P1 |

### 3.3 标签系统

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 手动打标签 | 在笔记编辑/对话时手动输入标签 | P0 |
| 预设标签推荐 | 根据用户身份推荐对应标签（小说/产品/内容） | P1 |
| 按标签筛选 | 查看某个标签下的所有笔记 | P1 |

### 3.4 AI功能

| 功能 | 描述 | 优先级 |
|------|------|--------|
| AI总结 | 自动总结笔记要点 | P0 |
| AI灵感工作台 | 根据笔记内容做灵感提取、对话和延展 | P1 |

### 3.5 消息/对话

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 创建对话 | 创建新的对话会话 | P1 |
| 发送消息 | 在对话中发送消息 | P1 |
| AI回复 | AI自动回复消息 | P1 |

## 4. Non-Functional Requirements

### 4.1 性能

- 笔记列表加载: < 1秒
- 笔记创建响应: < 500ms
- AI功能响应: < 5秒

### 4.2 可用性

- 移动端优先设计
- 3步内完成核心操作
- 支持离线创建笔记（后续同步）

### 4.3 安全

- 密码加密存储 (pbkdf2_sha256)
- Token-based认证
- 数据隔离（用户只能看到自己的笔记）

## 5. Technical Architecture

### 5.1 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | Flutter (移动端) |
| 后端 | FastAPI (Python) |
| 数据库 | SQLite (开发) / PostgreSQL (生产) |
| AI | 阿里云DashScope |
| 部署 | 待定 |

### 5.2 API设计

```
POST   /auth/register     # 注册
POST   /auth/login        # 登录
GET    /notes             # 获取笔记列表
POST   /notes             # 创建笔记
GET    /notes/{id}        # 获取笔记详情
PUT    /notes/{id}        # 更新笔记
DELETE /notes/{id}        # 删除笔记
POST   /notes/{id}/summarize  # AI总结
POST   /conversations         # 创建灵感工作台会话
POST   /conversations/{id}/message  # 发送 AI 对话消息
POST   /conversations/{id}/close    # 关闭会话并生成总结
```

## 6. UI/UX Requirements

### 6.1 页面结构

1. **登录/注册页** - 简洁的表单
2. **首页（笔记列表）** - 笔记卡片列表 + 新建按钮
3. **笔记详情页** - 笔记内容 + 操作按钮
4. **创建/编辑页** - 简单的文本编辑

### 6.2 设计原则

- 简洁干净，不要干扰用户记录
- 突出内容，弱化交互元素
- 移动端优先，优化单手操作
